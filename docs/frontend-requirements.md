# 前端开发需求文档

## 1. 项目定位

本项目为一款移动优先的情侣陪伴类 Web App，参考图中 `TwoDays` 的粉色、柔和、轻量仪式感风格，核心围绕“两个人每天共同完成一件小事”展开。

前端需要实现类似原型中的 10 类界面：

1. 登录/加入关系页
2. 首页仪表盘
3. 目标页
4. 气持ち/心情日记页
5. 日历页
6. 我的页面
7. 打卡完成反馈页
8. 目标达成反馈页
9. 对方一言/消息页
10. 等待对方打卡状态页

建议首期按移动端 Web App/PWA 开发，桌面端以手机画布居中展示，不优先做复杂自适应桌面布局。

## 2. 视觉风格分析

### 2.1 整体气质

参考图整体风格为日系轻甜、柔和、治愈感强的情侣应用。界面大量使用白色卡片、浅粉背景、圆角按钮、可爱插画、轻量图标和低对比度文字。

设计关键词：

- 温柔
- 亲密
- 轻量
- 仪式感
- 每日陪伴
- 双人共同完成

### 2.2 色彩规范

主色建议：

- 主粉色：`#FF5FA3`，用于主按钮、当前 Tab、进度条、重要状态。
- 浅粉色：`#FFB3C1`，用于装饰、轻量标签、头像背景、选中状态背景。
- 极浅粉背景：`#FFF7F9`，用于页面背景或模块背景。
- 白色：`#FFFFFF`，用于卡片、输入框、主要内容容器。
- 主文字：`#222222`，用于标题、金额、重点数字。
- 次级文字：`#888B8B`，用于说明、时间、辅助信息。
- 边框灰：`#F0E6EA`，用于卡片边界、分割线。
- 警示/强调红粉：`#FF3F7F`，用于目标差额、提醒。
- 成功绿：`#2BBF6A`，用于已完成、已查看、收入记录。

色彩使用要求：

- 页面背景应以浅粉或白色为主，避免大面积高饱和粉色。
- 主按钮使用粉色实底，按钮文字使用白色。
- 次按钮使用白底粉色描边。
- 正向金额或完成状态可使用绿色，但面积要小。
- 避免过多渐变；如果使用，只用于登录页背景或庆祝页氛围。

### 2.3 字体与排版

建议字体：

- 中文：系统默认无衬线字体，如 `PingFang SC`、`Microsoft YaHei`、`Noto Sans SC`。
- 数字金额：可使用系统字体加粗，不需要单独引入装饰字体。

字号建议：

- 页面标题：18px，字重 700。
- 卡片标题：14px-16px，字重 600。
- 正文：13px-14px。
- 辅助说明：11px-12px。
- 重点数字：28px-32px，字重 700。
- 底部导航文字：10px-11px。

排版特点：

- 内容区宽度按 375px 移动端设计稿优先。
- 页面左右安全边距 16px。
- 卡片内边距 14px-18px。
- 模块间距 12px-16px。
- 重要反馈页采用居中排版，垂直留白更大。

### 2.4 圆角、阴影与边框

参考图具有明显圆润风格：

- 页面级手机容器：24px。
- 卡片：12px-16px。
- 输入框：10px-12px。
- 主按钮：999px 胶囊圆角。
- 图标按钮：圆形或 10px-12px 圆角。

阴影应轻：

- 卡片阴影：`0 4px 16px rgba(255, 95, 163, 0.08)`。
- 弹层阴影：`0 8px 32px rgba(30, 20, 30, 0.12)`。

### 2.5 图标与插画

图中使用了以下视觉元素：

- 爱心 Logo
- 邮件、用户、铃铛、齿轮、日历、礼物等线性图标
- 情侣头像
- 情侣插画
- 小熊/爱心插画
- 云朵等待插画
- 纸条/剪贴板装饰
- 花瓣、闪光、彩纸等轻量装饰

实现要求：

- 常规 UI 图标优先使用图标库，例如 `lucide-react`。
- 情侣、熊、云朵、花瓣等可爱插画可用静态图片、SVG 或设计师提供资源。
- 首页、成就页、等待页必须有明显情绪化插画，否则会失去参考图的产品气质。
- 动效可用于庆祝页、按钮点击、Tab 切换和进度条增长，但首期不做复杂动画。

## 3. 页面结构与路由

建议路由如下：

| 路由 | 页面 | 说明 |
| --- | --- | --- |
| `/login` | 登录/加入关系页 | 输入邮箱、验证码、邀请码 |
| `/` 或 `/home` | 首页仪表盘 | 展示双方状态、连续打卡、今日一言入口 |
| `/goal` | 目标页 | 展示共同目标、进度、历史记录 |
| `/mood` | 心情页 | 选择今日心情、写日记、看时间线 |
| `/calendar` | 日历页 | 月视图查看双方记录 |
| `/profile` | 我的页面 | 关系信息、邀请码、设置入口 |
| `/checkin/success` | 打卡完成页 | 今日打卡完成反馈 |
| `/goal/success` | 目标达成页 | 目标完成反馈 |
| `/message/:id` | 对方一言页 | 查看/回复对方的今日留言 |
| `/waiting` | 等待对方页 | 自己已完成但对方未完成 |

底部导航固定 5 个 Tab：

1. 首页
2. 目标
3. 气持ち/心情
4. 日历
5. 我的

登录页、完成反馈页、目标达成页、消息详情页、等待页不显示或弱化底部导航，按业务状态决定。

## 4. 页面需求

### 4.1 登录/加入关系页

目标：让用户通过邮箱验证码登录，并用邀请码加入或创建双人关系。

主要元素：

- 顶部状态栏模拟区域或真实浏览器顶部留白。
- 居中爱心 Logo。
- 产品名：`TwoDays` 或后续确定的新品牌名。
- 副标题：`2人だけの特別な場所` 或中文等价文案。
- 邮箱输入框。
- 验证码输入框。
- 发送验证码按钮。
- 邀请码输入框，提示“有邀请码时填写”。
- 主按钮：`はじめる` 或 `开始`。
- 底部提示：需要邀请码/邀请码由伴侣提供。
- 背景可使用浅粉渐变、花瓣、光点、爱心装饰。

交互要求：

- 邮箱格式校验。
- 验证码倒计时。
- 邀请码可选；如果没有邀请码，可进入创建关系流程。
- 登录中按钮 loading。
- 登录失败显示轻量 Toast 或表单错误。

### 4.2 首页仪表盘

目标：展示情侣关系状态和今日最重要任务。

主要模块：

- 顶部情侣头像叠放。
- 双方昵称，例如 `ゆうた & さくら`。
- 关系天数，例如 `一緒に過ごして 12日目`。
- 右上角通知铃铛。
- 连续打卡卡片：
  - 火焰图标
  - 标题 `連続チェックイン`
  - 连续天数，例如 `5日目`
  - 主按钮 `今日もチェックインする`
  - 纸条/爱心装饰插画
- 对方今日状态卡片：
  - 对方头像
  - 気分/心情
  - ひとこと/一句话
  - 已查看状态
- 今日一言输入区：
  - 输入框
  - 发送按钮

交互要求：

- 点击连续打卡按钮进入心情页或直接进入打卡流程。
- 点击对方状态进入消息详情。
- 首页要区分以下状态：
  - 今日双方都未打卡
  - 当前用户已打卡，对方未打卡
  - 对方已打卡，当前用户未打卡
  - 双方都已打卡
- 今日一言发送后更新首页与消息页。

### 4.3 目标页

目标：展示情侣共同目标，例如一起存钱、旅行基金、纪念日计划等。

主要元素：

- 页面标题：`二人の目標`
- 编辑入口。
- 目标名称，例如 `一緒に10万円貯める`。
- 情侣插画。
- 当前金额，例如 `¥70,000 / ¥100,000`。
- 粉色进度条。
- 完成百分比，例如 `70%`。
- 距离目标差额，例如 `あと ¥30,000 で目標達成！`
- 主按钮：`お金を追加する`
- 历史记录列表：
  - 日期
  - 操作人
  - 金额变化

交互要求：

- 点击添加金额弹出输入弹窗或进入添加页。
- 金额输入需要校验大于 0。
- 达成目标后跳转或弹出目标达成页。
- 支持目标编辑：目标名称、目标金额、封面插画。
- 历史记录按时间倒序。

### 4.4 心情/日记页

目标：完成每日心情选择、日记记录，并查看双方时间线。

主要元素：

- 页面标题：`今日の気分は？`
- 心情选择卡片：
  - 开心
  - 普通
  - 难过/不开心
- 日记输入框，placeholder：`今日の気持ちを日記に書いてみよう...`
- 字数计数，例如 `0/200`。
- 主按钮：`投稿する`
- 时间线列表：
  - 心情图标
  - 用户头像
  - 时间
  - 文案
  - 查看更多入口

交互要求：

- 心情必须选择。
- 日记可选或按产品策略设为必填。
- 字数限制 200。
- 当天只能提交一次，提交后可编辑或只读由产品策略决定。
- 对方未打卡时显示等待状态。
- 时间线支持加载更多。

### 4.5 日历页

目标：以月视图回顾双方打卡、个人记录和未记录日期。

主要元素：

- 月份标题，例如 `2024年5月`。
- 左右切换月份箭头。
- 星期栏。
- 日期网格。
- 不同记录状态标记：
  - 爱心：一起打卡
  - 黄色标记：只有自己
  - 蓝色标记：只有对方
  - 空心圆：未记录
- 当前选中日期高亮。
- 底部说明卡片：`ふたりの記録`

交互要求：

- 点击日期查看当天详情。
- 支持切换上月/下月。
- 禁止查看未来日期的记录详情，或显示“还没有记录”。
- 标记颜色与说明保持一致。

### 4.6 我的页面

目标：管理关系、邀请码、通知、隐私和数据导出。

主要元素：

- 顶部情侣头像与昵称。
- 关系状态，例如 `連携中`。
- 右上角设置齿轮。
- 邀请码卡片：
  - 邀请码，例如 `A8X2K`
  - 复制按钮
- 设置菜单：
  - 通知设置
  - 隐私设置
  - 数据导出
  - 帮助/联系我们
- 危险操作按钮：`関係を解除する`

交互要求：

- 复制邀请码后显示 Toast。
- 设置项可先做静态页或弹窗。
- 解除关系需要二次确认。
- 数据导出需要触发后端导出任务或下载链接。

### 4.7 打卡完成页

目标：提供每日打卡完成后的正向反馈。

主要元素：

- 标题：`チェックイン完了！`
- 爱心/小熊插画。
- 鼓励文案。
- 连续打卡天数卡片。
- 主按钮：返回首页。

交互要求：

- 页面进入时可播放轻量庆祝动画。
- 返回首页后首页状态更新。

### 4.8 目标达成页

目标：在共同目标完成时给出强反馈。

主要元素：

- 标题：`目標達成！`
- 彩纸装饰。
- 情侣插画。
- 祝贺文案。
- 主按钮：`次の目標を作る`
- 次按钮：`あとで考える`

交互要求：

- 点击创建新目标进入目标创建页。
- 以后再说返回首页或目标页。

### 4.9 对方一言/消息页

目标：查看与回复对方的今日留言。

主要元素：

- 顶部返回按钮。
- 标题：`さくらのひとこと`。
- 日期标签。
- 聊天气泡：
  - 对方消息粉色气泡
  - 自己回复白色气泡
  - 时间戳
- 底部输入框。
- 圆形发送按钮。

交互要求：

- 支持发送短消息。
- 消息为空时禁用发送按钮。
- 发送后滚动到底部。
- 可选支持删除自己消息。

### 4.10 等待对方页

目标：当前用户已完成今日打卡，但对方还未完成时显示。

主要元素：

- 标题：`まだ来てないよ...`
- 云朵表情插画。
- 文案：`さみしいよ... 待ってるね...`
- 主按钮：`もう一度チェックする`

交互要求：

- 点击按钮刷新今日双方打卡状态。
- 若对方已完成，跳转首页或消息详情。
- 若仍未完成，保持当前页并提示。

## 5. 组件需求

### 5.1 基础组件

必须实现以下基础组件：

- `Button`
  - primary
  - secondary
  - danger
  - ghost/icon
  - loading
  - disabled
- `Input`
  - 文本
  - 邮箱
  - 验证码
  - 金额
  - textarea
- `Card`
  - 默认白色卡片
  - 轻粉色卡片
  - 可点击卡片
- `Avatar`
  - 单人头像
  - 双人叠放头像
  - 默认头像
- `BottomTabBar`
- `Toast`
- `Modal`
- `ProgressBar`
- `CalendarMonth`
- `MoodSelector`
- `TimelineItem`
- `EmptyState`
- `LoadingState`

### 5.2 状态组件

需要统一设计以下业务状态：

- 未登录
- 加载中
- 空数据
- 对方未加入
- 对方未打卡
- 网络错误
- 提交成功
- 目标达成
- 关系解除确认

### 5.3 表单校验

统一要求：

- 输入框错误提示不应挤压布局，可显示在输入框下方。
- 主按钮在提交中进入 loading 状态。
- 表单提交失败时显示 Toast 和字段级错误。
- 金额、验证码、邮箱等字段必须做前端基础校验。

## 6. 交互与动效

建议动效：

- 页面切换：轻微 fade/slide。
- 主按钮点击：scale `0.98`。
- 进度条：从旧进度平滑过渡到新进度。
- 完成页：彩纸或花瓣轻量动画。
- Toast：从顶部或底部滑入。

限制：

- 动效不影响表单可用性。
- 首屏加载动画不超过 1 秒。
- 应尊重系统 `prefers-reduced-motion`。

## 7. 响应式与兼容性

首期设计目标：

- 主要适配宽度：320px-430px。
- 标准设计宽度：375px。
- 桌面端：页面主体最大宽度 430px，居中展示。
- iOS Safari、Android Chrome、桌面 Chrome/Edge 最新两个大版本。

安全区：

- 底部导航需要兼容 `safe-area-inset-bottom`。
- 顶部返回栏或标题栏需要兼容刘海屏。

## 8. 数据展示规则

### 8.1 日期

- 首页关系天数显示为第 N 天。
- 日历页按用户本地时区展示。
- 后端返回 ISO 时间，前端负责按本地时区格式化。

### 8.2 金额

- 默认显示日元风格 `¥70,000`，如果产品面向中文市场，可改为 `¥70,000` 或 `￥70,000`。
- 输入金额时不允许负数。
- 展示金额需要千分位。

### 8.3 情绪

首期三种心情：

- 开心：🙂 或自定义笑脸图标。
- 普通：😐。
- 难过：☹️。

后续可扩展为五种心情。

## 9. 前端接口依赖

前端至少依赖以下接口：

- 登录与验证码接口。
- 获取当前用户信息。
- 获取/创建/加入情侣关系。
- 获取首页概览。
- 提交今日打卡。
- 获取今日双方打卡状态。
- 获取心情时间线。
- 获取日历月数据。
- 获取/更新目标。
- 添加目标金额记录。
- 获取消息列表。
- 发送消息。
- 获取/更新我的页面设置。
- 数据导出。

接口字段以 `docs/backend-requirements.md` 为准。

## 10. 推荐技术栈

如果从零开发，建议：

- 框架：Next.js 或 Vite + React。
- 语言：TypeScript。
- 样式：Tailwind CSS、CSS Modules 或 UnoCSS，选择一种即可。
- 状态管理：TanStack Query + 少量本地状态。
- 表单：React Hook Form + Zod。
- 图标：lucide-react。
- 日期：dayjs 或 date-fns。
- PWA：后续可加 manifest 和 service worker。

## 11. 验收标准

前端首期验收条件：

- 登录页、首页、目标页、心情页、日历页、我的页面六个主页面可完整访问。
- 底部导航可正常切换并保持当前高亮。
- 首页能正确展示关系天数、连续打卡天数、双方状态。
- 用户能提交一次今日心情/日记并看到成功反馈。
- 目标页能展示进度并添加金额记录。
- 日历页能按月显示打卡状态。
- 我的页面能复制邀请码。
- 移动端 320px-430px 宽度下无明显文字溢出或元素重叠。
- 主要按钮、输入框、卡片视觉风格与参考图保持一致。

## 12. 可延期功能

以下功能可作为第二期：

- 复杂通知设置。
- 多目标管理。
- 图片日记。
- 语音留言。
- 纪念日提醒。
- 情侣主题换肤。
- PWA 离线缓存。
- 桌面端完整布局。
- 数据导出为 PDF。
