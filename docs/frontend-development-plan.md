# 前端开发计划

## 1. 开发目标

基于 `frontend-requirements.md`，前端首期目标是完成一个移动优先的情侣陪伴类 Web App MVP。

MVP 必须覆盖：

- 邮箱验证码登录页。
- 创建/加入情侣关系后的首页。
- 每日心情打卡与完成反馈。
- 共同目标展示与金额添加。
- 日历月视图。
- 我的页面与邀请码复制。
- 消息/今日一言基础查看与发送。
- 与后端 API 完成基础联调。

首期不追求复杂动画、主题换肤、图片上传、离线 PWA 和完整桌面端布局。

## 2. 推荐技术选型

默认前端技术栈：

| 类型 | 选型 | 说明 |
| --- | --- | --- |
| 框架 | Vite + React | 适合快速开发移动端 Web App |
| 语言 | TypeScript | 保证接口类型和组件类型安全 |
| 路由 | React Router | 页面路由清晰，适合单页应用 |
| 请求/缓存 | TanStack Query | 处理接口缓存、loading、错误和刷新 |
| 表单 | React Hook Form + Zod | 表单校验统一 |
| 样式 | Tailwind CSS 或 CSS Modules | 二选一，建议 Tailwind 快速实现 |
| 图标 | lucide-react | 覆盖底部导航、按钮、设置等常规图标 |
| 日期 | dayjs | 处理日历、关系天数、本地时间 |
| 测试 | Vitest + React Testing Library | 组件和工具函数测试 |
| E2E | Playwright | 验证核心流程 |

如果计划使用 Next.js，也可以复用本计划的模块划分，仅需调整路由与构建部署方式。

## 3. 目录结构建议

建议目录：

```text
src/
  app/
    App.tsx
    router.tsx
    providers.tsx
  assets/
    illustrations/
    icons/
  components/
    common/
    layout/
    business/
  features/
    auth/
    dashboard/
    checkin/
    goal/
    calendar/
    message/
    profile/
  hooks/
  lib/
    api/
    date.ts
    format.ts
    storage.ts
  styles/
  types/
  test/
```

组织原则：

- `components/common` 放纯 UI 组件。
- `components/business` 放可跨页面复用的业务组件。
- `features/*` 放页面、接口 hook、局部组件和模块逻辑。
- `lib/api` 放请求实例、API 方法和响应类型。
- 不在页面里直接散写复杂请求逻辑。

## 4. 开发里程碑

### M0：项目初始化与设计系统

目标：建立可运行的前端工程、路由、样式基础和核心组件。

预计产出：

- 本地开发服务器可运行。
- 移动端页面壳完成。
- 视觉变量、按钮、输入框、卡片、底部导航等基础组件完成。
- Mock 数据可支撑页面静态开发。

### M1：认证与关系入口

目标：完成登录页、验证码流程、邀请码加入和登录态管理。

预计产出：

- 用户可以输入邮箱、验证码、邀请码登录。
- 登录成功后进入首页。
- 未登录访问业务页会跳转登录页。
- token 持久化和刷新策略初步完成。

### M2：首页与每日打卡闭环

目标：完成 MVP 最核心的每日陪伴流程。

预计产出：

- 首页展示关系天数、头像、连续打卡、今日状态。
- 用户可以进入心情页选择心情并提交日记。
- 提交后进入打卡完成页或等待对方页。
- 首页状态可刷新并正确展示双方完成情况。

### M3：目标与日历

目标：完成共同目标和历史回顾能力。

预计产出：

- 目标页展示进度、金额、历史流水。
- 用户可添加目标金额。
- 目标达成后展示目标达成页。
- 日历页展示某月双方记录状态。

### M4：消息与我的页面

目标：完成基础互动和用户设置入口。

预计产出：

- 今日一言/消息页可以展示和发送消息。
- 我的页面展示邀请码、关系状态、设置入口。
- 邀请码复制可用。
- 解除关系弹窗和前端状态处理完成。

### M5：联调、测试与体验优化

目标：完成后端联调、移动端兼容、主要路径测试和视觉还原。

预计产出：

- 所有核心接口完成联调。
- 320px-430px 移动端宽度无明显溢出。
- Playwright 覆盖登录、打卡、目标、日历等流程。
- UI 与参考图风格基本一致。

## 5. 详细任务拆分

### FE-001 项目初始化

内容：

- 初始化 Vite + React + TypeScript 项目。
- 配置 ESLint、Prettier、TypeScript strict。
- 配置路径别名，例如 `@/components`、`@/features`。
- 配置基础环境变量：`VITE_API_BASE_URL`。
- 配置开发、构建、预览命令。

依赖：无。

验收标准：

- `npm run dev` 可启动。
- `npm run build` 可通过。
- TypeScript 无阻塞错误。

### FE-002 全局样式与主题变量

内容：

- 定义颜色、字号、间距、圆角、阴影。
- 实现移动端主容器，桌面端居中显示。
- 设置全局背景、字体、按钮 reset、输入框 reset。
- 处理 `safe-area-inset-bottom`。

依赖：FE-001。

验收标准：

- 页面最大宽度控制在 430px。
- 底部导航不遮挡内容。
- 主色、浅粉色、卡片样式与需求文档一致。

### FE-003 基础 UI 组件

内容：

- `Button`
- `Input`
- `Textarea`
- `Card`
- `Avatar`
- `ProgressBar`
- `Toast`
- `Modal`
- `LoadingState`
- `EmptyState`

依赖：FE-002。

验收标准：

- 组件支持 loading、disabled、错误态。
- 组件在 320px 宽度下不溢出。
- Story/demo 页面或组件示例可检查主要状态。

### FE-004 应用路由与布局

内容：

- 配置主路由。
- 实现 `MobileShell`。
- 实现 `BottomTabBar`。
- 实现需要隐藏底部导航的页面规则。
- 实现返回按钮和页面标题栏。

依赖：FE-003。

验收标准：

- 底部 5 个 Tab 可切换。
- 当前页面 Tab 高亮正确。
- 登录页、成功页不显示底部导航。

### FE-005 API 客户端与类型基础

内容：

- 封装 HTTP client。
- 支持 Authorization header。
- 统一处理错误响应。
- 定义通用响应类型。
- 定义主要业务类型：User、Relationship、Checkin、Goal、Message。
- 配置 TanStack Query Provider。

依赖：FE-001。

验收标准：

- API 方法不直接散落在页面组件中。
- 401 可触发登出或刷新 token 流程。
- 错误信息可以被 Toast 展示。

### FE-006 Mock 数据与开发开关

内容：

- 建立 Mock 数据文件。
- 为首页、目标、日历、消息提供静态 Mock。
- 支持在后端未完成时先开发页面。

依赖：FE-005。

验收标准：

- 无后端服务时仍可查看主要页面静态效果。
- 切换真实 API 和 Mock 的方式清晰。

### FE-007 登录页

内容：

- 实现邮箱输入。
- 实现验证码输入与发送按钮。
- 实现邀请码输入。
- 实现登录按钮。
- 实现登录页背景、Logo、标题和提示。
- 接入 `/auth/send-code` 和 `/auth/login`。

依赖：FE-003、FE-005。

验收标准：

- 邮箱格式错误有提示。
- 发送验证码后按钮倒计时。
- 登录成功写入 token 并跳转首页。
- 登录失败有 Toast 或字段错误。

### FE-008 登录态与路由守卫

内容：

- 实现 token 存储。
- 实现获取当前用户 `/me`。
- 实现未登录重定向。
- 实现登录后根据关系状态跳转。

依赖：FE-005、FE-007。

验收标准：

- 刷新页面后登录态仍可恢复。
- token 无效时回到登录页。
- 业务页不会在未登录状态下裸露。

### FE-009 首页仪表盘

内容：

- 接入 `/dashboard`。
- 展示情侣头像、昵称、关系天数。
- 展示连续打卡卡片。
- 展示对方今日状态卡片。
- 展示今日一言输入区。
- 处理今日不同打卡状态。

依赖：FE-003、FE-004、FE-005。

验收标准：

- 首页 loading、错误、空关系状态均可展示。
- 点击打卡按钮进入心情页。
- 点击对方状态进入消息页。
- 发送今日一言后首页更新。

### FE-010 心情打卡页

内容：

- 实现心情选择器。
- 实现日记输入和 200 字计数。
- 接入 `/checkins/today` 提交接口。
- 根据 `bothCompleted` 跳转成功页或等待页。
- 提交后刷新首页相关缓存。

依赖：FE-003、FE-005。

验收标准：

- 未选择心情不可提交。
- 超过字数不可提交。
- 提交中按钮 loading。
- 成功后路由跳转正确。

### FE-011 打卡完成页

内容：

- 实现完成标题、插画、连续天数卡片。
- 实现返回首页按钮。
- 可加入轻量庆祝动画。

依赖：FE-010。

验收标准：

- 从心情页提交成功后可进入。
- 返回首页后首页数据刷新。

### FE-012 等待对方页

内容：

- 接入 `/checkins/today` 查询接口。

依赖：FE-010。

验收标准：

### FE-013 目标页

## 6. 联调顺序

建议前后端按以下顺序联调：

1. `/auth/send-code`、`/auth/login`
2. `/me`
3. `/relationships/current`
4. `/dashboard`
5. `/checkins/today`
6. `/checkins/timeline`
7. `/goals/current`
8. `/goals/:goalId/entries`
9. `/calendar`
10. `/messages`
11. `/settings`

联调原则：

- 先跑通登录和 token，再做业务接口。
- 首页作为聚合接口，应在基础关系和打卡数据稳定后联调。
- 每个接口至少准备空数据、正常数据、错误数据三种状态。

## 7. 前端验收清单

MVP 完成时需要确认：

- 登录流程完整。
- 刷新页面后登录态正常。
- 首页能正确显示双方状态。
- 今日打卡流程完整。
- 对方未打卡时等待页可用。
- 目标页能展示和更新金额。
- 目标达成页可触发。
- 日历页能按月切换。
- 消息页能发送和查看消息。
- 我的页面能复制邀请码。
- 移动端宽度 320px-430px 无明显布局问题。
- 主要接口错误都有用户反馈。
- `npm run build` 通过。

## 8. 风险与处理建议

| 风险 | 影响 | 建议 |
| --- | --- | --- |
| 后端接口未按时完成 | 页面开发受阻 | 保留 Mock 数据和 API adapter |
| 插画资源缺失 | 视觉还原度不足 | 先使用占位插画，后续替换 |
| 打卡状态规则变化 | 首页和流程返工 | 后端统一返回状态枚举，前端少做推导 |
| 移动端浏览器差异 | 底部导航遮挡或输入框错位 | 早期就做 iOS Safari 和 Android Chrome 检查 |
| 日历状态复杂 | UI 和数据不一致 | 日历接口直接返回每天状态，不让前端自行合并 |

## 9. 推荐开发顺序

最小可用路径：

1. FE-001 至 FE-006：工程和基础设施。
2. FE-007 至 FE-008：登录闭环。
3. FE-009 至 FE-012：首页和打卡闭环。
4. FE-013 至 FE-015：目标闭环。
5. FE-016：日历回顾。
6. FE-017 至 FE-018：消息和我的页面。
7. FE-019 至 FE-021：错误、视觉、测试。

优先级最高的是登录、关系、首页、打卡，因为它们构成产品的每日使用闭环。
